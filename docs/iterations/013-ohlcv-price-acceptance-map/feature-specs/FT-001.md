## D-02: 输入规格
| 参数名 | 类型 | 必填 | 约束 | 默认值 | 示例 |
|--------|------|------|------|--------|------|
| symbol | string | 是 | 单一交易对标识，不允许混入多个资产 | - | `BTCUSDT` |
| timeframe | string | 是 | 单一周期标识，同一请求内必须一致 | - | `4h` |
| candles | array<object> | 是 | 长度 `>= 1`，按时间升序、连续，字段齐全 | - | 1~5000 根 K 线 |
| candles[].open | number | 是 | 必须为正数 | - | `67250.5` |
| candles[].high | number | 是 | `>= max(open, close, low)` | - | `67520.0` |
| candles[].low | number | 是 | `<= min(open, close, high)` | - | `66880.0` |
| candles[].close | number | 是 | 必须为正数 | - | `67110.2` |
| candles[].volume | number | 是 | `>= 0` | - | `1284.42` |
| candles[].timestamp | ISO 8601 string/integer | 是 | 不可重复、必须升序且连续；字符串必须为 ISO 8601 | - | `2026-03-30T08:00:00Z` |
| market_hint | string | 否 | 用于提示解释口径，不得改变核心算法 | `crypto` | `crypto` |

## D-03: 前置条件
- [ ] 输入仅包含单个交易对的数据
- [ ] 所有 K 线属于同一时间周期
- [ ] K 线列表按时间升序且连续排列
- [ ] K 线数量满足 `N >= 1`

## D-04: 正常输出
- 返回标准化后的分析输入对象
- 明确 `symbol`、`timeframe`、`sample_size`
- 明确历史价格范围 `price_min` / `price_max`
- 若 `market_hint` 缺失，按一期默认值 `crypto` 处理，但不改变通用字段语义

## D-05: 异常行为
| 错误码 | 触发条件 | 错误消息 |
|--------|---------|---------|
| INVALID_SAMPLE_SIZE | `candles.length < 1` | 历史 K 线数量不足，至少需要 1 根 |
| INVALID_ORDERING | 时间戳非升序、重复或存在缺口 | 输入 K 线时间序列必须严格升序、不可重复且连续 |
| MIXED_TIMEFRAME | 同一请求内周期不一致 | 输入数据必须来自同一时间周期 |
| INVALID_PRICE_RELATION | 任一 K 线不满足 OHLC 关系 | 存在非法 K 线价格关系，请检查 high/low/open/close |
| INVALID_VOLUME | 任一成交量为负数 | 成交量必须大于或等于 0 |

## D-06: 边界值
- 恰好 `1` 根 K 线必须可被接受
- `volume = 0` 的 K 线允许进入输入，但后续概率分配时可产生 0 贡献
- `high = low` 的十字 K 线必须被视为合法输入
- `market_hint` 可缺省，不得因此报错
- 字符串时间戳必须可被解析为 ISO 8601 时间点

## D-07: 后置条件

## D-09: 性能要求
- 在 `1000` 根 K 线输入下，纯校验与标准化目标耗时应小于 `50ms`
- 输入校验时间复杂度应保持线性，不得引入与 `micro_bins` 无关的重复扫描

## D-10: 安全要求
- 只接受结构化 OHLCV 数据，不执行任何输入中的可执行内容
- 必须限制输入文件为预期 JSON 结构，拒绝脚本片段和非数值型价格字段
- 错误消息可描述字段问题，但不得泄露宿主运行环境内部路径

## D-11: 并发要求
- 校验器必须是无状态组件，可被并发调用
- 不允许在输入校验阶段写入共享全局状态

## D-12: 数据一致性
- 标准化后的 `candles` 顺序必须与输入升序顺序一致
- `symbol`、`timeframe`、`sample_size` 与 `price_min/price_max` 必须来自同一批输入
- 任何校验失败都不得产出部分合法、部分非法的混合结果

## D-13: 可观测性
- 记录 `symbol`、`timeframe`、`sample_size`、校验耗时和失败错误码
- 校验失败日志必须能定位到字段级错误类型

## D-14: 部署约束
- 不依赖数据库、缓存或外部网络服务
- 必须可被 CLI 入口与后续 Web 结果消费链路复用
