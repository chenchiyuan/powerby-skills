# 网站设计语言提取与还原规范

- 版本：1.0.0
- 制定日期：2026-04-10
- 适用范围：面向“参考目标网站提取设计语言，并基于提取结果生成相似网页”的 Skill、规则引擎、页面生成器与验证工具
- 参考基线：Ant Design 设计规范、Design Token 思路、组件化设计系统方法

---

## 一、文档目标

本文档用于定义一套完整、准确、可量化的“网站设计语言提取规范”。

目标不是简单总结某个网站的视觉风格，而是建立一套可以被 Skill 执行、被程序消费、被验证复现的结构化规则体系，使系统能够：

1. 从目标网站提取设计语言。
2. 将设计语言转化为机器可读规则。
3. 基于规则生成风格、结构、交互均相似的网页。
4. 通过验证机制判断规则是否足够支撑高保真还原。

本规范要求最终抽取结果可以支持“设计语言级复现”，而不是单页截图级模仿。

---

## 二、问题定义

如果目标是“让 Skill 参考目标网站并自动生成相似网页”，则必须提取的不是零散的设计元素，而是一整套设计语言语法。

仅提取颜色、字体、阴影等局部视觉元素是不够的。要实现高保真还原，必须同时定义以下六层：

1. 价值观层：为什么这样设计。
2. 原则层：设计如何取舍。
3. Token 层：颜色、字体、间距、圆角、阴影、动效等最小变量。
4. 组件层：按钮、表单、列表、导航等组件规则。
5. 页面模式层：列表页、详情页、表单页、结果页等模板规则。
6. 实现与验证层：断点、状态机、证据链、可访问性和复现验收标准。

只有同时覆盖这六层，才具备完整的设计还原能力。

---

## 三、核心原则

### 3.1 规则必须可量化

每条规则都必须可被结构化表达，并能尽可能绑定数值、阈值、范围、优先级或条件。

### 3.2 规则必须可复用

提取结果必须描述“设计语言的通用规律”，而不是只描述某一页的偶然布局。

### 3.3 规则必须可验证

每条高优先级规则都应有来源证据，整体规则集必须可通过覆盖率与相似度指标进行验收。

### 3.4 规则必须支持生成

规则定义不能只为分析服务，还必须能直接服务于组件生成、页面拼装和样式实现。

### 3.5 规则必须区分显式事实与推断

从目标网站提取时，必须区分：

- 文档明确说明的规则
- 页面直接观察到的规则
- 基于多处证据推断出的规则

推断规则必须携带可信度标记。

---

## 四、范围定义

### 4.1 输入范围

设计语言提取可使用以下输入源：

- 目标网站真实页面
- 页面截图
- DOM 结构
- CSS 源码
- computed style
- design token / CSS variables
- 组件文档
- 品牌规范文档
- 多状态页面样本
- 多断点页面样本

### 4.2 输出范围

必须输出以下结构化产物：

- `design_values.json`
- `design_principles.json`
- `design_tokens.json`
- `semantic_rules.json`
- `component_rules.json`
- `pattern_rules.json`
- `content_rules.json`
- `verification_spec.json`

### 4.3 非目标范围

以下内容不属于本规范的直接交付物：

- 最终网页工程代码
- 自动化爬虫实现细节
- 品牌战略咨询报告
- 完整运营内容生产

---

## 五、设计语言完整规则定义

以下章节定义 Skill 必须关注并提取的完整规则集合。每一类规则都必须说明“定义内容、量化要求、用途”。

---

## 5.1 品牌与设计价值观规则

### 定义目的

用于描述目标网站背后的品牌表达、情绪气质和设计判断基线，决定生成结果“是否像同一个品牌/产品家族”。

### 必须提取的字段

- 品牌定位
  - 企业级 / 工具型 / 内容型 / 电商型 / 展示型 / 社区型 / 教育型等
- 主要用户群
  - 新手 / 高频用户 / 专业用户 / 管理者 / 决策者等
- 设计气质标签
  - 理性、专业、克制、活跃、友好、权威、科技、温暖、探索等
- 核心设计价值观
  - 如确定性、自然、效率优先、清晰优先、生长性等
- 视觉优先级排序
  - 信息清晰、操作效率、品牌表达、转化效率、视觉冲击等的优先级
- 反向约束
  - 该设计系统避免什么，例如避免过度装饰、避免多主按钮、避免高噪声视觉层级

### 量化要求

每条价值观必须定义：

- `name`
- `description`
- `ui_implications`
- `forbidden_patterns`
- `priority`

### 解释说明

价值观不是抽象口号，而是必须能落到 UI 决策。

例如：

- “确定性”应映射到：操作区最多一个主按钮、关键状态有明确反馈、危险操作需要确认。
- “克制”应映射到：页面主色占比受限、阴影层级少、字阶数量少、强调手段单一。

---

## 5.2 设计原则规则

### 定义目的

用于描述设计系统的判断方法和取舍逻辑，决定系统在面对复杂页面时如何维持一致性。

### 必须覆盖的原则类别

- 对齐
- 对比
- 重复
- 亲密性
- 简化交互
- 直截了当
- 提供邀请
- 巧用过渡
- 即时反应
- 足不出户

### 每条原则必须定义

- 原则名称
- 原则目标
- 适用对象
- 量化指标
- 正例
- 反例

### 量化示例

- 对齐
  - 文本基线对齐方式
  - 同级模块边缘对齐率
  - 栅格起止列一致性
- 对比
  - 页面中强调色数量上限
  - 字号层级差阈值
  - 主次按钮视觉差异阈值
- 重复
  - 同语义是否复用同组件
  - 同组件是否复用同 token
- 简化交互
  - 核心任务步数
  - 是否支持原地完成
  - 是否减少页面往返

### 解释说明

原则层定义的不是某一个值，而是系统的判断机制。Skill 后续在生成页面时，需要优先遵守原则，再选择具体样式。

---

## 5.3 Token 规则

### 定义目的

用于定义视觉系统的最小变量，是还原目标网站视觉体系的核心基础。

### Token 分层要求

必须分为三层：

1. Seed Token：设计意图源头。
2. Map Token：从 Seed 派生出的梯度变量。
3. Alias Token：组件直接消费的语义变量。

---

### 5.3.1 Seed Token

#### 必须提取

- `colorPrimary`
- `colorSuccess`
- `colorWarning`
- `colorError`
- `colorInfo`
- `fontFamilyBase`
- `fontSizeBase`
- `lineHeightBase`
- `fontWeightBase`
- `radiusBase`
- `borderWidthBase`
- `spacingBase`
- `shadowBase`
- `motionBase`
- `opacityBase`
- `densityMode`
- `themeMode`

#### 量化要求

- 每个种子变量必须有原始值
- 必须记录来源证据
- 必须标注是显式值还是推断值

#### 解释说明

Seed Token 是视觉系统的原始种子，后续颜色梯度、控件尺寸、语义色和组件风格都会从这里派生。

---

### 5.3.2 Map Token

#### 必须提取

- 主色阶梯
- 功能色阶梯
- 中性色阶梯
- 字体尺寸阶梯
- 行高阶梯
- 字重阶梯
- 间距阶梯
- 圆角阶梯
- 阴影阶梯
- 边框粗细阶梯
- 不透明度阶梯
- 动效时长阶梯
- easing 阶梯
- z-index 阶梯

#### 量化要求

- 每一类都要有完整数组或映射
- 每个值要标记使用频率
- 每个值要标记主要适用对象

#### 解释说明

Map Token 是设计系统的“梯度层”，负责表达一个系统内部的节奏、层次和密度。

---

### 5.3.3 Alias Token

#### 必须提取

- 文本语义
  - `colorTextPrimary`
  - `colorTextSecondary`
  - `colorTextTertiary`
  - `colorTextDisabled`
  - `colorTextInverse`
- 背景语义
  - `colorBgPage`
  - `colorBgContainer`
  - `colorBgElevated`
  - `colorBgMask`
  - `colorBgHover`
  - `colorBgActive`
- 边框语义
  - `colorBorder`
  - `colorBorderSecondary`
  - `colorBorderFocus`
  - `colorBorderDanger`
- 反馈语义
  - `colorSuccessBg`
  - `colorWarningBg`
  - `colorErrorBg`
  - `colorInfoBg`
- 控件语义
  - `controlHeightSm`
  - `controlHeightMd`
  - `controlHeightLg`
  - `controlPaddingInline`
  - `controlPaddingBlock`
- 层级语义
  - `shadowCard`
  - `shadowPopover`
  - `shadowModal`
- 动效语义
  - `motionDurationFast`
  - `motionDurationBase`
  - `motionDurationSlow`
  - `motionEaseEnter`
  - `motionEaseExit`

#### 量化要求

- Alias Token 必须可直接映射到组件
- 不能只保留原始颜色，而不定义语义用途

#### 解释说明

Alias Token 是设计系统真正用于生成组件的语义层，没有这一层就无法稳定生成页面。

---

## 5.4 色彩系统规则

### 定义目的

用于定义目标网站中的颜色不是“有哪些”，而是“如何使用、如何组合、如何表达层级与状态”。

### 必须提取

- 品牌色
- 功能色
- 中性色
- 数据可视化色
- 插画/装饰色
- 特殊营销色

### 每类颜色必须定义

- 主值
- 色阶
- 色相/明度/饱和度特征
- 语义用途
- 使用比例
- 允许搭配
- 禁止搭配
- 文本叠加规则
- 深浅模式差异
- 无障碍对比规则

### 量化要求

- 统计全站主色面积占比
- 统计高饱和颜色出现频率
- 统计背景色层级数量
- 统计文本颜色层级数量
- 记录链接色、hover 色、选中色、禁用色

### 解释说明

颜色提取不能停留在“主色 = 某个蓝色”，而要建立一套完整的颜色语义与使用规则。

---

## 5.5 字体系统规则

### 定义目的

用于定义信息层级、阅读节奏和品牌气质，是页面“可读性”和“风格一致性”的关键部分。

### 必须提取

- 字体栈
- 备用字体策略
- 基础字号
- 标题字阶
- 正文字阶
- 注释字阶
- 数字字阶
- 行高体系
- 字重体系
- 字间距规则
- 大小写规则
- 数字是否等宽
- 中英混排规则
- 标题与正文对比规则
- 单页最多允许的字阶数量

### 量化要求

- 提取每个字号的真实使用频率
- 每个字号绑定行高与字重
- 标题层级必须定义 H1-H6 或等价层级
- 正文至少定义 primary、secondary、meta 三层文本语义

### 解释说明

字体系统不仅决定阅读体验，也决定“气质是否一致”。对于企业级设计系统，字体规则往往高度克制且层级明确。

---

## 5.6 布局系统规则

### 定义目的

用于定义页面骨架、栅格关系、模块节奏和响应式结构。

### 必须提取

- 基准画板宽度
- 主断点
- 栅格系统
- 列数
- gutter
- 容器最大宽度
- 页面左右边距
- 区块上下间距
- Header 高度
- Sidebar 宽度
- 内容区域对齐基线
- 卡片布局规则
- 页面分栏规则
- 常见内容密度模式
- 宽屏/标准屏/窄屏切换策略

### 量化要求

- 至少记录 desktop、tablet、mobile 三套规则
- 记录 1 列、2 列、3 列、4 列布局出现条件
- 记录固定宽、流式、自适应容器的场景
- 提取首屏信息结构
- 提取页面模块顺序规律

### 解释说明

布局系统决定了页面的“骨架像不像”。若没有布局规则，只能模仿组件，无法复刻页面节奏。

---

## 5.7 图标系统规则

### 定义目的

用于定义图标的造型、节奏、线条与使用方式，是高保真还原中容易遗漏但影响巨大的细节层。

### 必须提取

- 图标风格
- 画板尺寸
- 安全区
- 出血位
- 线宽
- 圆角
- 端点类型
- 视觉重心
- 是否遵循偶数像素
- 常用尺寸档位
- 图标与文本间距
- 单色/多色规则
- 状态变化规则
- 图标按钮规范

### 量化要求

- 每类图标记录 stroke/fill 特征
- 区分导航图标、操作图标、状态图标、品牌图标风格差异
- 记录纯图标按钮是否强制 tooltip

### 解释说明

图标系统直接影响“同一设计语言中的细节统一感”。不同网站往往在这一层有明显个性。

---

## 5.8 阴影、边框与层级规则

### 定义目的

用于定义界面层级、浮层秩序和空间感。

### 必须提取

- 阴影层级数量
- 每层阴影 recipe
- 阴影方向
- blur / spread / alpha
- 边框粗细体系
- 边框颜色层级
- 分割线规则
- 圆角与层级关系
- z-index 体系
- 遮罩颜色与透明度

### 量化要求

- 为卡片、下拉、浮层、抽屉、弹窗建立层级映射
- 区分 hover 浮起与常驻浮层阴影差异
- 记录卡片默认是否带边框、阴影，或仅 hover 出现

### 解释说明

这一层定义的是“空间语言”。许多企业站点看起来专业或克制，往往与其层级系统高度相关。

---

## 5.9 动效与过渡规则

### 定义目的

用于定义交互反馈节奏，使生成页面不仅静态相似，也具有相似的动态体验。

### 必须提取

- 默认动效开启状态
- 动效时长分层
- easing 曲线
- 状态切换属性
- hover 动效
- active 动效
- focus 动效
- 弹层进入退出动效
- 抽屉动效
- 列表加载动效
- 骨架屏策略
- reduced-motion 策略
- 禁用动画场景

### 量化要求

- 提取 duration 数值
- 提取 easing 曲线
- 记录哪些组件使用 transform，哪些只用 opacity
- 记录哪些反馈必须即时，哪些允许延迟

### 解释说明

动效规则是设计语言的一部分。它不应被视为“锦上添花”，而应视为交互系统中的节奏层。

---

## 5.10 文案系统规则

### 定义目的

用于定义系统如何“说话”，是品牌表达和可用性的重要组成部分。

### 必须提取

- 叙述视角
- 语气风格
- 标题规则
- 正文规则
- 按钮文案规则
- 表单提示文案规则
- 错误文案规则
- 成功文案规则
- 空状态文案规则
- 确认弹窗文案规则
- 术语词典
- 禁用同义词
- 日期/数字/单位表达规则

### 量化要求

- 按钮文案是否必须为动词
- 错误提示是否包含原因与建议动作
- 空状态是否必须包含下一步引导
- 标题、描述、说明文建议长度区间
- 术语必须统一

### 解释说明

文案规则不能只做情绪描述，而应转换为可执行的语义模板和术语约束。

---

## 5.11 导航系统规则

### 定义目的

用于定义信息架构的入口、路径和切换逻辑。

### 必须提取

- 导航模式
- 一级导航数量范围
- 导航文字长度
- 当前项高亮方式
- 悬停反馈方式
- 展开/收起逻辑
- 面包屑层级限制
- Tabs 数量建议
- Steps 步数建议
- 分页组件规范
- 导航跳转层级控制
- 导航与页面标题关系

### 量化要求

- 提取导航栏高度
- 提取选中态颜色、背景、字重、标识方式
- 提取折叠侧栏宽度
- 记录是否支持记忆上次展开状态
- 记录是否存在“就地切换”优先于“跨页跳转”

### 解释说明

导航系统直接决定产品的可理解性，也是页面结构高度稳定的一层规则。

---

## 5.12 按钮与操作规则

### 定义目的

用于定义操作优先级、操作区布局与交互风格。

### 必须提取

- 按钮类型
- 按钮尺寸
- 按钮形状
- 图标位置
- loading 态
- disabled 态
- hover / active / focus 态
- 按钮组规则
- 操作区布局规则
- 操作顺序规则
- 溢出折叠规则
- 单屏 CTA 数量限制

### 量化要求

- 每个操作区最多主按钮数
- 主次按钮视觉差定义
- 纯图标按钮是否强制 tooltip
- 文案是否限制为动词短语
- 危险操作是否与默认操作隔离

### 解释说明

按钮不是独立元素，而是整套操作语义系统的可视化出口，因此必须定义得非常清楚。

---

## 5.13 表单与输入规则

### 定义目的

用于定义录入效率、输入清晰度与错误反馈方式。

### 必须提取

- 表单布局模式
- 标签位置
- 必填标记
- 帮助文本位置
- 校验时机
- 错误信息位置
- 占位符使用规则
- 输入框尺寸
- 输入控件间距
- 分组与分段规则
- 搜索栏规则
- 筛选器规则
- 日期、选择器、开关、上传等控件规则

### 量化要求

- 标签与输入框对齐方式
- 表单项垂直间距
- 是否允许 placeholder 替代 label
- 错误信息是否占位、是否推开布局
- 必填、可选、推荐项的视觉标识

### 解释说明

表单规则属于高频交互规则，抽取不完整将直接导致生成结果可用性不足。

---

## 5.14 数据展示与列表规则

### 定义目的

用于定义业务型页面的主展示模式，是企业级产品复现的关键部分。

### 必须提取

- 列表类型
- 排序规则
- 筛选规则
- 搜索规则
- 工具栏规则
- 批量操作规则
- 新建入口位置
- 详情入口方式
- 分页方式
- 回退恢复规则
- 新增后插入位置
- 删除确认策略
- 空结果策略
- 长文本截断策略

### 量化要求

- 记录表头样式
- 记录 hover 行、选中行、斑马纹规则
- 记录表格密度模式
- 记录列表项最小高度
- 记录卡片列表列数变化规则
- 记录操作列位置与固定策略

### 解释说明

如果目标网站是企业后台、SaaS 平台或工作台系统，这一层通常比营销视觉更重要。

---

## 5.15 反馈、状态与空状态规则

### 定义目的

用于定义系统如何响应用户动作、任务结果和异常情况。

### 必须提取

- 反馈类型
- 严重级别
- 是否打断流程
- 自动消失时长
- 是否允许堆叠
- 表单反馈规则
- 异步任务反馈规则
- 空状态分类
- 空状态结构
- 错误恢复入口
- 重试机制

### 量化要求

- 每种反馈组件定义触发场景
- 定义优先级和打断级别
- 定义空状态最少组成元素
- 定义错误信息是否必须包含下一步动作

### 解释说明

反馈系统是可用性的核心。如果不能正确建模反馈机制，就无法真正还原目标网站的交互体验。

---

## 5.16 页面模板规则

### 定义目的

用于定义页面级的结构组合规则，而不是单组件堆叠。

### 必须覆盖的页面类型

- Landing Page
- Dashboard / Workbench
- List Page
- Detail Page
- Form Page
- Result Page
- Search Page
- Settings Page
- Auth Page
- Exception Page

### 每种模板必须定义

- 页面目标
- 信息架构
- 区块顺序
- 标题区结构
- 操作区位置
- 筛选区位置
- 内容容器形式
- 推荐组件组合
- 默认留白
- 响应式变化
- 空态/加载态/错误态模板

### 量化要求

- 必须记录页面骨架结构
- 必须记录主次区块比例
- 必须记录首屏优先信息
- 必须记录模板级交互规则

### 解释说明

页面模板是 Skill 从“组件生成”升级到“页面生成”的关键层。

## 5.17 组件目录规则

### 定义目的

用于建立 Skill 的组件字典，作为规则复用和页面组合的基础。

### 必须覆盖的组件目录

- 基础原子
  - Typography、Icon、Divider、Surface、Spacer、Container
- 布局
  - Flex、Stack、Grid、Split、Cluster、Section
- 导航
  - Header、Sidebar、Menu、Breadcrumb、Tabs、Steps、Pagination
- 操作
  - Button、ButtonGroup、Dropdown、Tooltip、Popconfirm
- 录入
  - Input、Textarea、Select、Radio、Checkbox、Switch、DatePicker、Upload、SearchBar、FilterPanel

  - Table、List、Card、Tag、Badge、Avatar、Statistic、DescriptionList、Chart、Empty、Skeleton、Progress

### 每个组件必须定义

- `interaction_rules`

### 解释说明

组件规则必须既能指导实现，又能指导自动生成器进行正确组合。

## 5.18 响应式与设备适配规则

### 定义目的

用于保证 Skill 生成结果不是只会生成桌面版，而是能跨断点保留设计语言一致性。

### 必须提取

- 断点体系
- 每个断点的容器宽度
- 栅格变化
- 字号变化
- 间距变化
- 导航切换策略
- 卡片列数变化
- 表格降级策略
- 弹层变抽屉规则
- 操作区折叠策略
- 图片裁切策略

### 量化要求

- 至少记录 desktop、tablet、mobile
- 必须记录哪些组件在移动端换形
- 必须记录哪些信息在小屏折叠或隐藏
- 必须记录表格如何降级为卡片或列表

### 解释说明

响应式不是附加项，而是页面模式的一部分。高保真还原必须覆盖不同屏幕的行为。

---

## 5.19 可访问性与工程约束规则

### 定义目的

用于确保生成的设计系统不仅“像”，而且“可用、可实现、可维护”。

### 必须提取

- 文本对比度
- 非文本对比度
- 焦点态可见性
- 键盘可达性
- 点击热区最小尺寸
- 表单标签语义
- 异步反馈可读性
- reduced motion 支持
- 国际化长度弹性
- 长文本截断与 tooltip 策略
- 日期/数字/单位格式化规范
- 图标替代文本规则

### 量化要求

- 对比度等级
- focus ring 的颜色、粗细、偏移
- 最小点击区域
- 键盘导航顺序与可见状态
- 组件是否必须具备 aria 语义

### 解释说明

若缺少这一层，系统生成的只是“看起来像”的静态页面，而不是可靠的产品级界面。

---

## 5.20 证据链与可信度规则

### 定义目的

用于控制规则抽取的可信度，避免规则只来自主观判断。

### 每条规则必须可关联的证据类型

- screenshot
- dom
- css
- computed_style
- token
- docs
- inferred

### 每条证据必须包含

- `source_type`
- `source_ref`
- `confidence`
- `notes`

### 量化要求

- 视觉规则至少有一个证据来源
- 推断规则必须显式标注
- 高优先级规则应尽量双证据验证

### 解释说明

证据链是本规范的关键约束。没有证据链，Skill 的结果难以复用，也无法稳定验证。

## 六、提取工作流要求

Skill 在执行时，至少应遵循以下工作流：

1. 建立页面样本集
   - 至少覆盖首页、列表页、详情页、表单页、弹层页、空状态页、错误页。
2. 提取全局 Token
   - 先提颜色、字体、间距、圆角、阴影、动效、断点。
3. 提取语义映射
   - 建立文本、背景、边框、反馈、控件、层级等 Alias Token。
4. 提取组件规则
   - 从基础原子到复合组件逐级归档。
5. 提取页面模板
   - 将页面按固定 pattern 分类并归纳结构。
6. 提取文案与反馈规则
   - 建立系统语气、错误、空状态、按钮文案规则。
7. 建立验证样本集
   - 选择代表性页面和状态作为还原校验样本。
8. 执行复现验证
   - 对照 schema 完整性、规则覆盖率与页面相似度进行校验。

---

## 七、验收与验证标准

必须定义以下验收指标：

### 7.1 Token 完整率

- 颜色、字阶、间距、圆角、阴影、边框、动效、断点完整提取率 = 100%

### 7.2 组件覆盖率

- 页面中出现过的核心组件规则覆盖率 >= 95%

### 7.3 状态覆盖率

- 核心组件 default、hover、active、focus、disabled、loading、error、empty 覆盖率 = 100%

### 7.4 页面模板覆盖率

- 核心页面类型覆盖率 = 100%

### 7.5 响应式覆盖率

- desktop、tablet、mobile 覆盖率 = 100%

### 7.6 语义映射完整率

- 高频样式映射到 Alias Token 的比例 >= 95%

### 7.7 证据完整率

- 高优先级规则有来源证据支撑率 = 100%

### 7.8 复现相似度

- 人工评审“风格一致性”通过
- 关键页面截图 diff 相似度 >= 95%

### 7.9 可用性验证

- 核心路径任务可完成
- 关键组件状态可用
- 小屏布局可用

## 八、Skill 的功能需求

Skill 至少需要支持：

- 输入一个目标网站或页面集合
- 输出标准化规则文件
- 标注每条规则的来源与可信度
- 支持补充提取和增量更新
- 支持按页面、组件、规则类型查询
- 支持导出为生成器可消费格式
- 支持在规则不完整时发出缺失提醒
- 支持验证“当前规则是否足够重建某页面”

---

## 九、Skill 的非功能需求

- 输出结构必须稳定，适合程序消费
- 规则命名必须统一规范
- 同一语义必须避免重复定义
- 必须支持扩展，不同网站可复用同一 schema
- 允许保留站点特有规则
- 支持显式规则与推断规则并存，但必须标记可信度

## 十一、结论

这套规范的本质不是“总结一个站的视觉风格”，而是建立一套完整的设计语言提取协议。它要求：

- 能描述品牌气质
- 能量化视觉变量
- 能建模组件和页面模板
- 能覆盖状态与响应式
- 能标记证据和可信度
- 能通过验证证明足够支撑还原

只有满足以上条件，Skill 才能从“设计观察器”升级为“设计语言复现器”。
