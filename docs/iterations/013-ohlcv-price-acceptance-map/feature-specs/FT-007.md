## D-01: 功能标识
- **全局唯一 ID**: FT-007
- **入口类型**: CLI 命令
- **入口路径**: `python -m powerby.cli acceptance-map`

## D-02: 输入规格
| 参数名 | 类型 | 必填 | 约束 | 默认值 | 示例 |
|--------|------|------|------|--------|------|
| input_file | string | 是 | 指向 OHLCV 数据文件 | - | `./data/btcusdt-4h.json` |
| output_format | string | 否 | 一期固定支持 `json` | `json` | `json` |
| partition_mode | string | 否 | `adaptive_volatility` 或 `equal_width` | `equal_width` | `equal_width` |
| include_heatmap | boolean | 否 | 是否输出热力图数据 | `true` | `true` |
| include_diagnostics | boolean | 否 | 是否输出诊断字段 | `true` | `false` |

## D-03: 前置条件
- [ ] 输入文件存在且可读取
- [ ] 文件内容可被解析为合法 OHLCV 数据
- [ ] 输出格式为一期支持的 `json`

## D-04: 正常输出
- 命令执行成功后返回完整 JSON 结果
- JSON 至少包含：
  - 输入摘要
  - 底层热力图或其开关结果
  - 区域列表
  - 参数摘要
- 退出码为 0

## D-05: 异常行为
| 错误码 | 触发条件 | 错误消息 |
|--------|---------|---------|
| INPUT_FILE_NOT_FOUND | 输入文件不存在 | 指定的 OHLCV 输入文件不存在 |
| INPUT_PARSE_ERROR | 输入文件无法解析 | 输入文件无法解析为合法 OHLCV 数据 |
| UNSUPPORTED_OUTPUT_FORMAT | 请求非 `json` 输出格式 | 当前版本仅支持 JSON 输出 |
| ANALYSIS_FAILED | 下游分析流程失败 | 价格接受度分析失败，请检查错误详情 |

## D-06: 边界值
- 最小合法输入文件必须包含 1 根 K 线
- `include_heatmap = false` 时仍必须输出区域列表
- `include_diagnostics = false` 时仍必须输出主概率结果

## D-07: 后置条件
- [ ] 用户可在命令行直接获得结构化分析结果
- [ ] JSON 输出可被脚本、服务或页面直接消费

## D-08: 副作用
- 将分析结果写到标准输出
- 产生 CLI 退出码和错误消息

## D-09: 性能要求
- 在 `1000` 根 K 线输入下，CLI 端到端分析目标耗时应小于 `1s`
- CLI 序列化 JSON 的附加耗时应小于 `100ms`

## D-10: 安全要求
- CLI 只允许读取用户指定的本地 OHLCV 文件
- 不执行文件内容中的脚本、不动态导入用户路径
- 错误输出不得泄露宿主系统敏感环境信息

## D-11: 并发要求
- CLI 单次执行按单请求模型运行，不共享跨进程状态
- 多个 CLI 进程同时运行时不得争用共享临时结果

## D-12: 数据一致性
- CLI 参数必须完整透传到分析核心，尤其是 `partition_mode`、`include_heatmap`、`include_diagnostics`
- 标准输出 JSON 必须与 `AcceptanceMapResult` 契约一致
- 成功退出码与失败退出码必须与错误状态一致

## D-13: 可观测性
- 记录输入文件路径摘要、`partition_mode`、运行耗时和退出状态
- 失败时记录对应错误码，不吞掉下游分析异常

## D-14: 部署约束
- CLI 入口部署在同一代码仓库内，直接调用分析核心
- 一期不要求独立二进制打包或远程服务部署
