# FT-005: reviewer 自动回流判断

## 基本信息
- **Feature ID**: FT-005
- **功能名称**: reviewer 自动回流判断
- **对应需求**: F-005
- **功能类型**: 审查层
- **优先级**: 必须（P0）
- **状态**: 待实现

## D-01: 功能标识
- **Feature ID**: FT-005
- **入口类型**: Skill（orchestrator 内部判断 + reviewer SKILL.md 升级）
- **入口路径**: `skills/pb-v1-orchestrator/SKILL.md`, `skills/pb-v1-reviewer/SKILL.md`

## D-02: 输入规格
| 参数名 | 类型 | 必填 | 约束 | 默认值 | 示例 |
|--------|------|------|------|--------|------|
| review_result | object | 是 | reviewer 输出的审查报告 | - | { status: "FAIL", issues: [...] } |
| review_type | enum | 是 | prd/architecture/plan/implementation | - | "prd" |
| refinery_round | integer | 是 | 当前 Refinery 轮次，≥ 1 | 1 | 2 |

## D-03: 前置条件
- reviewer 已执行并返回 FAIL 结果
- 审查报告包含结构化的 issues 列表（每个 issue 有 severity 和 evidence）

## D-04: 正常输出
orchestrator 对 FAIL 做前置判断，输出三种决策之一：

| 判断结果 | 条件 | 后续动作 |
|---------|------|---------|
| AUTO_DECIDE（自动回流） | issues 全部 MINOR/MAJOR 且修复路径明确 | 调度责任 Skill 修复，自动重新 review |
| USER_GATE_REQUIRED | issues 中有任何一条指向上游约束问题或范围变更 | 停止调度，交还用户 |
| ESCALATE_TO_USER | refinery_round ≥ 3 | 停止调度，G5 升级给用户 |

回流时 orchestrator 构建修复上下文：
- FAIL issues 列表（具体问题 + 证据位置）
- 原始目标（本轮 Skill 的验收标准）
- 文档地址（需要修改的产物路径）

## D-05: 异常行为
| 错误码 | 触发条件 | 行为 | 错误消息 |
|--------|---------|------|---------|
| ERR-REFLOW-001 | issues 列表为空但 status 为 FAIL | 升级给用户 | "reviewer FAIL 但无具体 issues，请确认" |
| ERR-REFLOW-002 | 无法识别责任 Skill | 升级给用户 | "无法确定修复责任方: {issue_summary}" |
| ERR-REFLOW-003 | 修复后产物未变化 | 计入 Refinery 轮次 | "修复后产物无变化，Refinery 轮次 +1" |

## D-06: 边界值
- issues 全部 MINOR → AUTO_DECIDE
- issues 含 1 个 BLOCKER → USER_GATE_REQUIRED（BLOCKER 意味着下游无法开始）
- issues 含 MAJOR 但指向上游约束 → USER_GATE_REQUIRED（不是修复能解决的）
- refinery_round = 3 → ESCALATE_TO_USER（G5）
- refinery_round = 2 且 issues 与上轮相同 → 仍尝试一次，第 3 轮再升级

## D-07: 后置条件
- 判断结果已记录到 flow-state.md 的 Refinery 记录
- AUTO_DECIDE 时责任 Skill 已被调度（auto 模式）
- USER_GATE_REQUIRED/ESCALATE 时用户已收到通知

## D-08: 副作用
- 更新 flow-state.md（Refinery 记录追加）
- AUTO_DECIDE 时触发责任 Skill 的 agent 调度
- 修复完成后自动触发 reviewer 重新审查

## 测试维度

### D-17: Test Oracle
**成功输出 Schema**:
```yaml
reflow_decision:
  result: enum [AUTO_DECIDE, USER_GATE_REQUIRED, ESCALATE_TO_USER]
  responsible_skill: optional string
  fix_context:
    issues: array
    original_goal: string
    doc_paths: array
```

**业务规则**:
- BLOCKER issue → 必须 USER_GATE_REQUIRED，不可 AUTO_DECIDE
- refinery_round ≥ 3 → 必须 ESCALATE_TO_USER，无论 issue 类型
- AUTO_DECIDE 后必须自动调度修复 + 重新 review
- 上游约束问题 → USER_GATE_REQUIRED，即使 severity 是 MINOR

- reviewer FAIL 报告：MAJOR 但指向上游（→ USER_GATE_REQUIRED）

## 架构维度

### D-09: 性能要求
- 回流判断延迟：即时（基于 issues 列表的规则判断，无 I/O）

### D-10: 安全约束
- 回流判断不修改任何产物
- ESCALATE 决策必须交还用户，不可系统自行绕过

### D-11: 幂等性
- 同一 review_result + refinery_round 输入产生相同判断结果

### D-12: 事务性
- Refinery 记录追加到 flow-state.md，原子写入

### D-13: 可观测性
- 每次回流判断记录到 flow-state.md Refinery 记录区块
- 判断结果通过状态通知（FT-004）输出给用户

### D-14: 降级策略
- issues 列表为空但 FAIL → 升级给用户
- 无法识别责任 Skill → 升级给用户
- refinery_round ≥ 3 → G5 强制升级

### D-15: 依赖关系
- **上游**: reviewer completion_signal（含 review_result + reflow_recommendation）
- **上游**: flow-state.md（Refinery 轮次记录）
- **下游**: 责任 Skill（被回流调度）
- **下游**: reviewer（修复后重新审查）
- **Feature 依赖**: FT-002（调度器执行回流）、FT-003（状态记录）、FT-004（通知用户）

### D-16: 实现映射
- **入口文件**: skills/pb-v1-orchestrator/SKILL.md（回流判断逻辑）+ skills/pb-v1-reviewer/SKILL.md（reflow_recommendation 输出）
- **核心变更**: orchestrator 新增回流判断引擎，reviewer 新增 reflow_recommendation 字段
- **变更类型**: MODIFIED（两个 Skill 协同变更）
