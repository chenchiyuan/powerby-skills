# pb-v1 Skill 协议合规升级计划

**版本**: 1.0.0
**创建日期**: 2026-04-20
**目标**: 将 22 个 pb-v1 Skill 升级至 Skill Design Protocol v3.1.0
**原则**: 奥卡姆剃刀——最小化变更，只补缺失项，不重构已有内容

---

## 升级维度

| 维度 | 代号 | 说明 | 影响范围 |
|------|------|------|---------|
| Role 定义 | R | 添加 identity(L4) + relationship + character | 21/22（verifier 已有） |
| 约束词分级 | C | 审计现有约束词，按四级体系规范化 | 22/22 |
| 上下文管理 | X | Workflow 中添加上下文管理建议（非强制） | 按需 |
| 验证者集成 | V | 标注哪些 Skill 适合触发 Agent-Gate | 按需 |
| 文件大小 | S | 超 800 行的拆分或精简 | 2/22（brower 857, designing 872） |

---

## 通用升级模板

每个 Skill 的升级步骤：

1. **R** — 在 frontmatter 中添加 `role:` 字段（identity + relationship + character）
2. **C** — 扫描现有隐式约束，按四级体系标注关键的 2-3 条；CRITICAL ≤3
3. **X** — 如 Workflow 涉及多轮交互或大产出，添加上下文管理建议
4. **V** — 如产出物有下游消费方且可验证，标注 Agent-Gate 触发点
5. **S** — 如超 800 行，识别可精简内容

## 执行优先级

| 优先级 | Skill | 原因 |

| P0 | ui-review | 14 CRITICAL 严重超标，需立即修复 |
| P0 | designing, brower, demo | 超 800 行需精简 |
| P0 | verifier | CRITICAL 需从 6 降至 ≤3 |
| P1 | orchestrator | 编排器是核心，需先升级以协调其他 Skill |
| P1 | clarify → planning → drafting | 上游链路，按顺序升级 |
| P1 | implementing → frontend → testing | 执行链路 |
| P1 | reviewer, spec-verify | 验证链路，需明确与 verifier 的关系 |
| P2 | shipping, preview, demo | 辅助类 Skill |
| P2 | discovery, retrospective, office-hours, talk | 非核心链路 |
| P2 | ascii, design-system | 工具类 Skill |

## 执行方式

- 每个 Task 独立执行，完成后标记 ✅
- 每个 Skill 修改后，确保 SKILL.md 仍符合协议模板结构
- Role 定义需达到 L4 精度（交叉稀缺 × 具象类比 × 战绩暗示）
- 约束词总量控制：CRITICAL ≤3/Skill，MUST/NEVER ≤2/Section
- 不重构现有内容，只补充缺失的协议要求项
