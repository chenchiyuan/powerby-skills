# FT-007: 核心 skill 对接协议

## 基本信息
- **Feature ID**: FT-007
- **功能名称**: 核心 skill 对接协议
- **对应需求**: F-007
- **功能类型**: 对接层
- **优先级**: 必须（P0）
- **状态**: 待实现

## D-01: 功能标识
- **Feature ID**: FT-007
- **入口类型**: Skill（多个 SKILL.md 升级）
- **入口路径**:
  - `skills/pb-v1-drafting/SKILL.md`
  - `skills/pb-v1-designing/SKILL.md`
  - `skills/pb-v1-planning/SKILL.md`
  - `skills/pb-v1-implementing/SKILL.md`

## D-02: 输入规格
| 参数名 | 类型 | 必填 | 约束 | 默认值 | 示例 |
|--------|------|------|------|--------|------|
| dispatch_context | object | 是 | orchestrator 传入的 4 项上下文 | - | { goal, scope, verification, doc_paths } |

每个被调度的 Skill 接收 orchestrator 构建的调度上下文：

| 字段 | 说明 |
|------|------|
| goal | 本次 agent 需要达成的可验证目标 |
| scope | 本次 agent 的工作边界 |
| verification | 如何判断目标达成 |
| doc_paths | agent 需要读取的关键文档路径 |

## D-03: 前置条件
- Skill 被 orchestrator 通过 Agent 工具调度
- dispatch_context 4 项齐备
- Skill 自身的前置产物存在（由 orchestrator 在调度前验证）

## D-04: 正常输出
每个 Skill 完成后输出结构化的完成信号：

```yaml
completion_signal:
  skill: string          # Skill 名称
  status: enum           # completed | failed | blocked
  artifacts:             # 产出的文件路径列表
    - path: string
      type: string       # proposal | feature-spec | architecture | tasks | code | test-report
  issues: optional array # 执行中遇到的问题（blocked 时必填）
    - description: string
      gate_candidate: optional enum [G1, G2, G3, G4, G5]
  assumptions: optional array  # AUTO_DECIDE_WITH_ASSUMPTION 决策（已写入 clarifications/）
    - clr_id: string     # CLR-AUTO-{NNN}
      summary: string
```

orchestrator 基于此信号判断 Gate 并决定下一步。

## D-05: 异常行为
| 错误码 | 触发条件 | 行为 | 错误消息 |
|--------|---------|------|---------|
| ERR-DOCK-001 | dispatch_context 缺少必填字段 | Skill 拒绝执行 | "调度上下文不完整，缺少: {fields}" |
| ERR-DOCK-002 | 前置产物不存在 | 返回 blocked + 问题描述 | "前置产物缺失: {path}" |
| ERR-DOCK-003 | Skill 执行中遇到需要用户决策的问题 | 返回 blocked + gate_candidate | "需要用户决策: {description}" |

## D-06: 边界值
- dispatch_context 只有 3 项（缺 1 项）→ ERR-DOCK-001
- Skill 执行成功但无产物变化（如 reviewer PASS 无修改）→ status: completed, artifacts: []
- Skill 执行中产生多个 assumption → assumptions 数组包含全部
- Skill 执行中同时遇到 blocked 和 assumption → 先记录 assumption，再返回 blocked

## D-07: 后置条件
- Skill 产出的文件已写入文件系统
- 完成信号已返回给 orchestrator
- AUTO_DECIDE_WITH_ASSUMPTION 决策已写入 clarifications/（通过 FT-006）

## D-08: 副作用
- 创建或更新产物文件（各 Skill 各自的产物）
- 可能写入 clarifications/（通过 clarify）
- 不修改 flow-state.md（由 orchestrator 负责）

## 架构维度

### D-09: 性能要求
- completion_signal 生成延迟：即时（Skill 执行完成后构建返回值）
- dispatch_context 解析延迟：即时

### D-10: 安全约束
- dispatch_context 不含完整文档内容（只传路径）
- completion_signal 不含敏感信息

### D-11: 幂等性
- Skill 本身的幂等性不变（由各 Skill 自身保证）
- completion_signal 是执行结果的快照，不影响幂等性

### D-12: 事务性
- Skill 产物写入与 completion_signal 返回是两步操作
- 产物先写入文件系统，再返回 signal（保证产物存在性）

### D-13: 可观测性
- completion_signal 包含 artifacts 列表，orchestrator 可验证产物存在性
- assumptions 列表提供 auto_decided 决策的追溯入口

### D-14: 降级策略
- dispatch_context 缺少必填字段 → Skill 拒绝执行，返回 ERR-DOCK-001
- 前置产物不存在 → 返回 blocked + 问题描述

### D-15: 依赖关系
- **上游**: orchestrator dispatch_context（4 项上下文）
- **下游**: orchestrator（消费 completion_signal）
- **涉及 Skill**: drafting、designing、planning、implementing（4 个核心 Skill 统一变更）

### D-16: 实现映射
- **入口文件**: skills/pb-v1-drafting/SKILL.md, skills/pb-v1-designing/SKILL.md, skills/pb-v1-planning/SKILL.md, skills/pb-v1-implementing/SKILL.md
- **核心变更**: 每个 Skill 的输出协议新增 completion_signal 章节，输入协议新增 dispatch_context 接收
- **变更类型**: MODIFIED（4 个 Skill 统一扩展）
