# FT-008: Web 可视化结果页

## 基本信息
- **Feature ID**: FT-008
- **功能名称**: Web 可视化结果页
- **对应需求**: REQ-010
- **功能类型**: entry
- **优先级**: P1
- **状态**: draft

---

## D-01: 功能标识
- **全局唯一 ID**: FT-008
- **入口类型**: Web 页面
- **入口路径**: `acceptance-map` 结果展示页

## D-02: 输入规格
| 参数名 | 类型 | 必填 | 约束 | 默认值 | 示例 |
|--------|------|------|------|--------|------|
| analysis_result | object | 是 | 必须来自 FT-006 或 FT-007 的 JSON 结果 | - | 1 次分析结果 |
| view_mode | string | 否 | 一期支持 `heatmap+regions` | `heatmap+regions` | `heatmap+regions` |
| selected_region_id | string | 否 | 若存在，必须属于区域列表中的 `region_id` | `null` | `R-003` |

## D-03: 前置条件
- [ ] 已获得合法的分析结果 JSON
- [ ] 结果中至少包含区域列表
- [ ] 若展示热力图，结果中必须包含底层价格轴数据

## D-04: 正常输出
- 页面展示价格接受度热力图
- 页面展示区域列表，并按概率排序
- 页面允许查看单个区域的区间和主概率
- 页面可直接消费 CLI 或服务输出的 JSON 结果

## D-05: 异常行为
| 错误码 | 触发条件 | 错误消息 |
|--------|---------|---------|
| RESULT_SCHEMA_INVALID | 传入结果不符合预期结构 | 分析结果结构非法，无法渲染 |
| HEATMAP_DATA_MISSING | 请求热力图展示但缺少底层数据 | 缺少热力图数据，无法绘制价格接受度图 |
| REGION_NOT_FOUND | 指定区域不存在 | 选择的区域不存在 |

## D-06: 边界值
- 仅有区域列表、无热力图数据时，页面仍应展示区域结论
- 仅 1 个区域时，页面仍必须可渲染
- 区域数较多时，列表排序仍必须稳定

## D-07: 后置条件
- [ ] 人工交易员可通过页面理解历史高接受度价格区
- [ ] 页面不需要反向定义算法，只消费合同结果

## D-08: 副作用
- 生成面向人工交易员的视觉输出
- 影响后续产品闭环验证体验

## D-09: 性能要求
- 在 `100` 个热力图单元、`20` 个区域下，首屏渲染目标时间应小于 `1.5s`
- 区域切换与高亮交互目标响应时间应小于 `100ms`

## D-10: 安全要求
- 页面只消费分析结果 JSON，不执行 JSON 中的脚本内容
- 渲染层必须对文本字段进行转义，避免结果内容被直接注入页面 DOM

## D-11: 并发要求
- 多个浏览器会话可同时查看同一分析结果而不共享可变状态
- 页面状态切换不得修改原始分析结果对象

## D-12: 数据一致性
- 页面展示的区域排序必须与结果 JSON 中的排序一致
- 热力图边界、区域区间和选中态必须共享同一结果对象
- 当缺少热力图时，页面必须退化为仅展示区域列表，而不是生成伪热力图

## D-13: 可观测性
- 记录页面渲染成功/失败、热力图是否启用、区域数量和渲染耗时
- 对 `RESULT_SCHEMA_INVALID` 与 `HEATMAP_DATA_MISSING` 记录明确前端错误状态

## D-14: 部署约束
- Web 结果页作为消费层部署，不依赖额外在线分析 API
- 一期允许以静态页面 + JSON 结果文件的方式运行
