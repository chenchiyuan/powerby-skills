# FT-005: AUTO-FIX / ASK / ESCALATE 决策系统

## 基本信息
- **Feature ID**: FT-005
- **功能名称**: AUTO-FIX / ASK / ESCALATE 决策系统
- **对应需求**: REQ-007, REQ-008, REQ-009, REQ-011
- **功能类型**: 决策机制
- **优先级**: 必须
- **状态**: 待实现

## D-01: 功能标识
- **Feature ID**: FT-005
- **入口类型**: Decision Engine
- **入口路径**: `skills/pb-review-v2/references/decision-table.md`

## D-02: 输入规格
| 参数名 | 类型 | 必填 | 约束 | 默认值 | 示例 |
|--------|------|------|------|--------|------|
| finding | object | 是 | 包含 severity, confidence, evidence | - | - |
| context | object | 是 | 包含 stage, round, scope | - | - |

## D-03: 前置条件
- Finding 已完成 confidence 分级
- Evidence 已收集

## D-04: 正常输出
```yaml
decision: enum [AUTO-FIX, ASK, ESCALATE]
reason: string
fix_instruction: object (仅 AUTO-FIX)
```

## D-05: 异常行为
| 错误码 | 触发条件 | 行为 |
|--------|---------|------|
| ERR-DEC-001 | 缺少 confidence | 默认 ASK |

## D-06: 边界值
- C1/C2 + 任何 severity → 不能 AUTO-FIX
- Round > 3 → 强制 ESCALATE
- 无 evidence → 不能 AUTO-FIX

## D-07: 后置条件
- 决策结果可被编排器执行

## D-08: 副作用
- 无副作用（纯决策）

## D-17: Test Oracle
**业务规则**:
- C1/C2 禁止 AUTO-FIX
- 职责内 + C3/C4 + 证据充分 → 必须 AUTO-FIX
- Round > 3 → 必须 ESCALATE

## D-18: Fixture Contract
**最小数据集**:
- 决策表测试用例矩阵

## D-20: Coverage Claim
- **决策路径覆盖**: 100%

## D-09: 性能要求
- **响应时间**: 单个决策 < 1 秒
- **吞吐量**: 每次审查处理 1~50 个 Findings
- **资源消耗**: 低（纯逻辑判断）

## D-10: 安全要求
- **数据隐私**: 不上传用户文档
- **权限控制**: 只读取 references/decision-table.md
- **输入验证**: 验证 Finding 结构完整性（severity, confidence, evidence）

## D-11: 并发要求
- **并发模式**: 无并发需求
- **冲突处理**: 不适用

## D-12: 数据一致性
- **幂等性**: 同一 Finding 重复决策产生相同结果
- **确定性**: 决策表是确定性的，无随机因素

## D-13: 可观测性
- **日志**: 决策结果写入审查报告的 Findings 部分
- **追踪**: 通过 Finding ID 追踪决策过程
