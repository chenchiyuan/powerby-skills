# FT-001: 通用 ASP Reviewer Skill 核心框架

## 基本信息
- **Feature ID**: FT-001
- **功能名称**: 通用 ASP Reviewer Skill 核心框架
- **对应需求**: REQ-001, REQ-006
- **功能类型**: 核心能力
- **优先级**: 必须
- **状态**: 待实现

## D-01: 功能标识
- **Feature ID**: FT-001
- **入口类型**: Skill
- **入口路径**: `skills/pb-review-v2/SKILL.md`

## D-02: 输入规格
| 参数名 | 类型 | 必填 | 约束 | 默认值 | 示例 |
|--------|------|------|------|--------|------|
| iteration_dir | string | 是 | 必须是有效的迭代目录路径 | - | `docs/iterations/014-asp-review-skill-upgrade/` |
| review_target | string | 否 | 可选指定审查对象文件 | 自动识别 | `proposal.md` |
| round | integer | 否 | 轮次编号，>= 1 | 1 | 1 |

## D-03: 前置条件
- 迭代目录存在且包含至少一个可审查文档
- `docs/consitution.md` 存在
- `docs/asp-document-protocol.md` 存在
- `docs/skill-design-protocol.md` 存在

## D-04: 正常输出
- 审查报告文件：`{stage}_logs/round-{N}-claude.md`
- 报告包含：Reviewer、Round、Stage、Alignment Summary、Findings、Decision、Evidence、Status
- Status 为 PASS 或 FAIL

## D-05: 异常行为
| 错误码 | 触发条件 | 行为 | 错误消息 |
|--------|---------|------|---------|
| ERR-REV-001 | 迭代目录不存在 | 快速失败 | "迭代目录不存在: {path}" |
| ERR-REV-002 | 无可审查文档 | 快速失败 | "迭代目录中无可审查文档" |
| ERR-REV-003 | 宪法文件缺失 | 快速失败 | "docs/consitution.md 不存在" |
| ERR-REV-004 | 协议文件缺失 | 快速失败 | "ASP 文档协议文件不存在" |

## D-06: 边界值
- 空迭代目录 → ERR-REV-002
- 轮次 > 3 → 自动 ESCALATE
- 无历史审查记录 → 视为第 1 轮

## D-07: 后置条件
- 审查报告文件已创建
- 报告格式符合统一模板
- 历史审查记录可被后续轮次读取

## D-08: 副作用
- 创建或追加 `{stage}_logs/` 目录
- 写入审查报告文件
- 不修改被审查文档

## D-17: Test Oracle
**成功输出 Schema**:
```yaml
reviewer: string (Claude|Codex|其他)
round: integer >= 1
stage: enum [product, spec, architecture, plan, implementation]
alignment_summary: object
  - upstream_complete: boolean
  - downstream_clean: boolean
  - gaps: array
findings: array
  - id: string
  - severity: enum [BLOCKER, MAJOR, MINOR]
  - confidence: enum [C1, C2, C3, C4]
  - evidence: array
status: enum [PASS, FAIL, ESCALATED]
```

**业务规则**:
- Alignment Summary 必须在 Findings 之前
- C1/C2 问题不能标记为 AUTO-FIX
- 第 4 轮必须 ESCALATE

## D-09: 性能要求
- **响应时间**: 单次审查 < 2 分钟（产品阶段），< 5 分钟（架构阶段）
- **吞吐量**: 单用户单迭代，无并发需求
- **资源消耗**: 内存占用 < 500MB，CPU 占用 < 50%

## D-10: 安全要求
- **数据隐私**: 不上传用户文档到外部服务
- **权限控制**: 只读取迭代目录和 docs/ 目录，只写入 {stage}_logs/
- **输入验证**: 验证迭代目录路径，防止路径遍历攻击

## D-11: 并发要求
- **并发模式**: 单用户单迭代，不支持并发审查
- **锁机制**: 无需锁机制（单线程执行）
- **冲突处理**: 不适用（无并发场景）

## D-12: 数据一致性
- **事务性**: 审查报告写入为原子操作
- **幂等性**: 同一轮次重复执行产生相同结果
- **一致性保证**: 历史审查记录与当前状态一致

## D-13: 可观测性
- **日志**: 审查报告文件 `{stage}_logs/round-{N}-claude.md`
- **指标**: 无需额外指标（报告中包含 Status、Round、Findings 数量）
- **追踪**: 通过 Round 编号追踪审查历史

## D-14: 部署约束
- **运行环境**: Claude Code CLI 或 Desktop App
- **依赖**: 无外部依赖，只依赖文件系统
- **配置**: 通过 references/ 目录配置审查清单和决策表
