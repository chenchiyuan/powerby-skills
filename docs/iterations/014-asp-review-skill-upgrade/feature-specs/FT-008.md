## D-06: 边界值
- 无修复指令 → 不触发 Fixer
- 所有指令为 ASK → 等待用户决策
- 混合指令 → 先执行 AUTO-FIX，再 ASK 剩余

## D-07: 后置条件
- 编排器协议文档已定义
- Reviewer 和 Fixer 的 I/O 契约明确

## D-08: 副作用
- 触发 Fixer skills 执行修复
- 触发 Reviewer 复审

## D-09: 性能要求
- **响应时间**: 协议解析 < 1 秒
- **吞吐量**: 单次调度
- **资源消耗**: 低

## D-10: 安全要求
- **数据隐私**: 不上传用户文档
- **权限控制**: 通过编排器调度，不直接访问文件
- **输入验证**: 验证修复指令格式

## D-11: 并发要求
- **并发模式**: 串行执行（Reviewer → Fixer → Reviewer）
- **冲突处理**: 不适用

## D-12: 数据一致性
- **契约一致性**: Reviewer 输出格式与 Fixer 输入格式一致
- **版本兼容**: 协议版本化，支持向前兼容

## D-13: 可观测性
- **日志**: 调度记录
- **追踪**: 通过 Round 编号追踪
