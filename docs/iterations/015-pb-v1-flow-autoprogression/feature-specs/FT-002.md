# FT-002: orchestrator 中心调度器

## 基本信息
- **Feature ID**: FT-002
- **功能名称**: orchestrator 升级为中心调度器
- **对应需求**: F-002
- **功能类型**: 调度层
- **优先级**: 必须（P0）
- **状态**: 待实现

## D-01: 功能标识
- **Feature ID**: FT-002
- **入口类型**: Skill
- **入口路径**: `skills/pb-v1-orchestrator/SKILL.md`

## D-02: 输入规格
| 参数名 | 类型 | 必填 | 约束 | 默认值 | 示例 |
|--------|------|------|------|--------|------|
| flow_state | document | 是 | flow-state.md 存在于迭代目录 | 初始化新状态 | docs/iterations/015/flow-state.md |
| last_skill_result | object | 否 | 上一个 agent 的执行结果 | 无（首次启动） | { skill: "drafting", status: "completed", artifacts: [...] } |
| user_instruction | string | 否 | 用户主动指令 | 无 | "mode: manual" |

## D-03: 前置条件
- docs/pb-v1-protocol.md 存在（协议是调度的依据）
- 迭代目录存在
- 至少有一个可调度的 Skill（即流程未完成）

## D-04: 正常输出
- orchestrator 通过 Agent 工具调度目标 Skill，传入 4 项上下文：
  - 目标：本次 agent 需要达成的可验证目标
  - 范围：本次 agent 的工作边界
  - 验证方法：如何判断目标达成
  - 文档地址：agent 需要读取的关键文档路径
- agent 在独立 context window 中执行
- agent 返回后，orchestrator 判断 Gate 并决定下一步
- 输出状态通知给用户（详见 FT-004）

## D-05: 异常行为
| 错误码 | 触发条件 | 行为 | 错误消息 |
|--------|---------|------|---------|
| ERR-ORC-001 | 协议文档缺失 | 快速失败 | "docs/pb-v1-protocol.md 不存在，无法调度" |
| ERR-ORC-002 | agent 执行异常退出 | 记录失败，评估是否重试 | "agent({skill}) 异常退出: {error}" |
| ERR-ORC-003 | Gate 判断无法确定 | 升级给用户 | "无法判断是否命中 Gate，请确认: {context}" |
| ERR-ORC-004 | flow-state.md 与文件系统不一致 | 以文件系统为准，修正状态 | "flow-state.md 状态已修正: {diff}" |

## D-06: 边界值
- 首次启动（无 flow-state.md）→ 初始化新状态，从 discovery 开始
- 流程已完成（所有 Skill 已完成）→ 输出完成通知，不再调度
- agent 返回空结果 → 视为失败，记录并评估
- 用户在 agent 执行中发送消息 → 中断当前调度，等待用户指令
- mode: manual → 不自动调度，只输出建议

## D-07: 后置条件
- flow-state.md 已更新（阶段进度、产物路径）
- 下一个 Skill 已被调度（auto 模式）或建议已输出（manual 模式）
- Gate 命中时用户已收到通知并等待决策

## D-08: 副作用
- 更新 flow-state.md
- 通过 Agent 工具创建子 agent 会话
- 向用户输出状态通知文本

## 架构维度

### D-09: 性能要求
- 单次调度延迟：取决于 Agent 工具启动时间（不可控）
- 全流程端到端：取决于各 Skill 执行时间
- 无并发需求（单用户单流程）

### D-10: 安全约束
- orchestrator 不传完整文档内容（最小上下文原则）
- agent 在独立 context window 中执行，互不影响

### D-11: 幂等性
- 调度是幂等的：同一状态下重复调度产生相同结果
- flow-state.md 是幂等性保证

### D-12: 事务性
- flow-state.md 更新是原子操作（单文件写入）
- agent 执行失败不影响 flow-state.md（先执行后更新）

### D-13: 可观测性
- 状态通知输出到用户对话（FT-004）
- flow-state.md 记录完整调度历史
- Gate 命中记录可追溯

### D-14: 降级策略
- agent 执行失败 → 记录失败，评估重试
- 连续 3 次失败 → G5 升级给用户
- mode: manual 降级为只读建议者

### D-15: 依赖关系
- **上游**: pb-v1-protocol.md（调度规则）
- **上游**: flow-state.md（当前状态）
- **下游**: 所有主线 Skill（被调度方）
- **工具**: Agent 工具（Claude Code 内置）
- **Feature 依赖**: FT-001（协议）、FT-003（状态）、FT-004（通知）、FT-005（回流）

### D-16: 实现映射
- **入口文件**: skills/pb-v1-orchestrator/SKILL.md
- **核心变更**: 红线声明重写、新增调度流程、新增 Gate 判断引擎、新增 completion_signal 消费
- **变更类型**: MODIFIED（重写）
