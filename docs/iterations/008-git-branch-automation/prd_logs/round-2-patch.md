### BLOCKER #001: 远程分支依赖未定义

**问题描述**: REQ-004 和 REQ-005 定义了删除远程分支和检查远程同步的 P0 能力，但 REQ-010（自动推送到远程仓库）已推迟到 P2，导致远程分支何时存在、未配置 remote 时如何处理等前置条件未声明，违反零假设原则。

### MAJOR #002: US-007 冲突检测流程死胡同

**问题描述**: US-007 使用 `git merge --no-commit --no-ff` 做冲突预检测，但未定义无冲突后如何回滚预检测现场，也未定义检测后何时执行 `git merge --abort`，导致仓库停留在中间合并态，形成流程死胡同。

**修复方案**: 明确定义冲突检测的完整流程：
- 有冲突时执行 `git merge --abort` 清理现场，列出冲突文件
- 无冲突时执行 `git merge --abort` 回滚预检测，然后执行正式合并
- 用户手动解决冲突后可重新触发合并流程

**修复位置**:
1. `spec.md:154-168` - US-007 业务规则增加 `git merge --abort` 清理逻辑和正式合并流程
2. `spec.md:309-327` - US-007 验收标准增加回滚预检测和重新触发合并的场景

**验证标准**:
- ✅ 冲突检测后仓库状态明确（已清理或已合并）
- ✅ 无冲突时有明确的正式合并路径
- ✅ 有冲突时有明确的清理和重试路径

### MAJOR #003: US-004 破坏性操作缺少错误路径

**问题描述**: US-004 是破坏性操作，但只定义了成功路径，未定义本地删除成功/远程删除失败、权限不足、远程分支不存在时的错误路径和最终状态。

**修复方案**: 补充完整的错误路径和状态定义：
- 本地和远程都删除成功 → `deleted`
- 本地删除成功但远程删除失败 → `deleted_local_only`，提示用户手动删除远程分支
- 远程分支不存在 → 仅删除本地分支，状态为 `deleted`

**修复位置**:
1. `spec.md:101-116` - US-004 业务规则增加部分失败场景和状态定义
2. `spec.md:253-270` - US-004 验收标准增加部分失败和远程不存在场景
3. `spec.md:382-389` - BranchStatus 枚举增加 `deleted_local_only` 状态
4. `spec.md:454-464` - 错误类型增加 `REMOTE_DELETE_FAILED`

**验证标准**:
- ✅ 所有可能的删除结果都有明确的状态归宿
- ✅ 部分失败时有清晰的错误信息和用户指引
- ✅ 数据字典包含所有可能的分支状态

### MAJOR #004: US-008 数据字典缺失

**问题描述**: US-008 要求生成分支历史报告，并列出"提交哈希、作者、时间、消息、合并者、合并提交哈希"等字段，但数据字典没有定义任何 `BranchHistoryReport` / `CommitRecord` / `MergeRecord` 实体，违反"显式优于隐式"原则。

**修复方案**: 在数据字典中补充完整的实体定义：
- `BranchHistoryReport`: 报告顶层结构（迭代ID、分支名、提交列表、合并记录、生成时间）
- `CommitRecord`: 提交记录（哈希、作者、邮箱、时间、消息）
- `MergeRecord`: 合并记录（合并提交哈希、合并者、邮箱、时间、源分支、目标分支）

**修复位置**:
1. `spec.md:378-403` - 数据字典增加 `BranchHistoryReport`、`CommitRecord`、`MergeRecord` 三个实体定义

**验证标准**:
- ✅ 所有 US-008 提及的字段都在数据字典中有明确定义
- ✅ 实体之间的关系清晰（Report 包含 Commits 和 MergeRecord）
- ✅ 所有字段都有类型、必填性、描述和示例值
