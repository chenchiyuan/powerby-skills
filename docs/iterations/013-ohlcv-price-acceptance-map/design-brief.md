## 4. Problem Statement

当前用户主要依靠主观经验识别交易对的支撑、阻力和共识价格区。这种做法不系统、不可复现，也难以稳定输出给程序或界面。用户希望基于单个交易对最近 N 根 OHLCV，构建一套结构化算法，把“历史价格在哪些区域被市场反复接受”表达为一张可计算、可视化、可消费的价格接受度地图。

## 5. Validation Goal

验证是否能从历史 OHLCV 中构建出一张对人工交易员有解释力的价格接受度地图，使其高概率区域在结构上能对应历史筹码密集区、反复震荡区或典型支撑阻力区，并且该结果能以稳定 JSON 输出供 CLI 和 Web 页面消费。

## 6. Target User and Status Quo

- **目标用户**: 人工交易员
- **次用户**: 使用结构化输出做过滤、打分或展示的策略程序
- **一期主场景**: 对单个交易对、单个周期、最近 N 根 OHLCV，按需生成一次价格接受度地图
- **主市场**: 加密货币
- **现状**:
  - 主要依赖人工经验判断共识区和支撑阻力
  - 缺乏统一算法口径
  - 不易输出给 CLI、服务接口和 Web 页面
- **现状代价**:
  - 同一数据集下的判断不可稳定复现
  - 无法批量、结构化消费
  - 很难形成后续产品化能力

## 7. Success Criteria

- 存在一套明确的 `price_acceptance_probability` 算法定义，输入为同一交易对、同一周期、最近 N 根 OHLCV
- 算法主口径清晰：时间衰减后的成交量按单根 K 线 `[low, high]` 覆盖范围均匀分配到细粒度价格单元
- 一期默认构建固定 `100` 个 `micro bins` 的底层价格轴
- 存在独立区域划分服务，并可把底层结果聚合为区域级输出
- 区域服务一期至少支持两种插件：
  - 波动自适应切分
  - 等宽切分
- 结果至少可输出给 CLI JSON，并可被 Web 页面可视化消费
- 一期主验收以“结构解释有效”为准，而不是未来收益、回测收益或前瞻触达精度

## 8. Constraints and Non-goals

- 一期不把“未来 H 根触达概率”作为主定义
- 一期不要求真实 intrabar 停留时间建模，只接受 K 线区间覆盖近似
- 一期不要求 tick size 对齐、盘口微观结构、委托簿建模
- 一期不以内嵌交易建议、下单信号、买卖点推荐为目标
- 一期只做基础输入合法性校验，不承担复杂脏数据修复
- 算法优先于 UI；CLI 和 Web 不能反向绑架算法定义

## 9. Premises

1. 历史价格接受度可以用历史 K 线覆盖行为近似表达，不必等待真实逐笔停留时间数据。
2. 成交量应作为价格接受的权重系数，而不是与价格表现完全平行的另一套主概率。
3. 越新的历史 K 线，对当前结构共识的解释力越强，因此需要时间衰减。
4. “区域划分”和“概率计算”应拆成两个层级，避免把区域插件和核心概率算法耦合在一起。
5. 对人工交易员来说，可解释性和结构直觉优先于复杂预测模型。

## 10. Alternatives Considered

### Approach A: 参考 demo，直接走“VAP + MC 终点分布 + 融合概率”路线

- **优点**:
  - 可以同时覆盖终点分布、目标价触达和 HVN/LVN 等多类输出
  - 参考材料完整，便于后续扩展
- **缺点**:
  - 会把结构接受度和未来事件概率混在一期主定义里
  - 对当前主目标“结构共识区识别”来说过重
  - 可解释性不一定优先，容易提前进入复杂预测模型

### Approach B: 以“价格接受度地图”为核心，未来概率模块暂时降级

- **优点**:
  - 与用户主目标一致，直接回答哪些价格区被历史更强烈地接受
  - 算法口径直观，适合人工交易员解释
  - 更容易稳定落地为 CLI JSON 和 Web 可视化
- **缺点**:
  - 一期不直接给出强定义的未来事件概率
  - 未来若要扩展终点分布或触达概率，需要再加上层模块

### Approach C: 将覆盖概率和成交量概率长期拆成两条平行主线

- **优点**:
  - 诊断性强，可分别观察“经过多”和“量大”的差异
  - 对研究阶段有帮助
- **缺点**:
  - 主输出会变得分散
  - 不符合用户后续收敛后的表达：成交量是权重，价格是表现，最终还是希望形成单一价格概率地图

## 11. Recommended Direction

选择 Approach B，并保留 Approach C 的诊断字段思想。

推荐路线如下：

- 核心主输出采用 `price_acceptance_probability`
- 底层先构建固定 `100` 个 `micro bins` 的细粒度价格轴
- 对每根 K 线，取其 `[low, high]` 覆盖到的 `micro bins` 集合，将 `time_weight * volume` 均匀分配到这些价格单元
- 对所有 K 线的贡献做累加和归一化，得到底层价格接受度分布
- 再由独立区域划分服务把底层分布聚合成区域级热力图和区域列表
- 保留 `coverage_count`、`weighted_volume_contribution` 作为辅助诊断信息，但不与主概率并列为双主线

选择该路线的原因是：它最贴近用户的真实问题，定义简单、结构清楚、易于解释，也最适合先完成算法优先的一期闭环。

## 12. Handoff to Proposal

后续 `proposal.md` 必须继承：

- **目标摘要**:
  - 基于单个交易对最近 N 根 OHLCV 构建价格接受度地图
  - 主目标是识别历史结构共识区 / 支撑阻力观察区
  - 输出既能给人工交易员看，也能被程序结构化消费

- **核心算法方向**:
  - 主概率定义为 `price_acceptance_probability`
  - 单根 K 线的贡献口径为 `[low, high]` 区间覆盖
  - 每根 K 线的 `time_weight * volume` 在覆盖到的底层价格单元中均匀分配
  - 时间权重服务支持多口径，一期只实现指数衰减
  - 底层 `micro price axis` 一期固定切成 `100` 个 `micro bins`

- **区域服务方向**:
  - 区域划分与概率计算分层
  - 区域必须完整覆盖历史价格范围且互不重叠
  - 一期区域插件至少支持：
    - 波动自适应切分
    - 等宽切分

- **交付要求**:
  - 主验收对象是算法与 JSON 输出
  - 需要可被 CLI 消费，并支持 Web 页面可视化
  - 结果至少应支持热力图全貌和区域列表结论两种表现形式

- **验证方式**:
  - 一期优先验证“结构解释有效”
  - 即高概率区域是否对应历史上直观可解释的筹码密集区、反复震荡区或支撑阻力区

- **输入约束**:
  - 同一交易对
  - 同一周期
  - 时间升序、连续
  - `N` 为用户自定义的正整数，默认值 `500`
  - 一期主市场默认加密货币，但设计上保持可泛化

- **明确排除**:
  - 不把未来 `H` 根事件概率作为一期主定义
  - 不在一期内承诺交易建议、自动下单信号、盘口级建模
  - 不把 demo 中的 Monte Carlo 融合方案直接当作一期主算法

- **仍待在 `proposal.md` 收敛的未决项**:
  - 区域插件的默认参数和切分细节
  - CLI 输入输出契约和 JSON schema
  - Web 页面的一期最小交互范围
  - 诊断字段和异常 / warning 规则的最终字段命名
