# FT-007: 标准 Review Loop

## 基本信息
- **Feature ID**: FT-007
- **功能名称**: 标准 Review Loop
- **对应需求**: REQ-012, REQ-013
- **功能类型**: 流程编排
- **优先级**: 必须
- **状态**: 待实现

## D-01: 功能标识
- **Feature ID**: FT-007
- **入口类型**: Workflow
- **入口路径**: Skill 主流程

## D-02: 输入规格
| 参数名 | 类型 | 必填 |
|--------|------|------|
| iteration_dir | string | 是 |
| max_rounds | integer | 否 |

## D-03: 前置条件
- Reviewer skill 已加载

## D-04: 正常输出
- 每轮包含：报告 + 修复指令 + 复审结论
- 最终 Status: PASS 或 ESCALATED

## D-06: 边界值
- Round > 3 → 强制 ESCALATE

## D-17: Test Oracle
**业务规则**:
- 第 4 轮禁止继续 AUTO-FIX
- 每轮有明确轮次编号

## D-19: Test Case Groups
| 测试组 | 用例数 | 优先级 |
|--------|--------|--------|
| 单轮通过 | 1 | P0 |
| 多轮收敛 | 2 | P0 |
| 超限 ESCALATE | 1 | P0 |

## D-20: Coverage Claim
- **循环路径覆盖**: 100%

## D-05: 异常行为
| 错误码 | 触发条件 | 行为 |
|--------|---------|------|
| ERR-LOOP-001 | Fixer 修复失败 | 记录失败，进入下一轮 |
| ERR-LOOP-002 | 复审时新增问题 | 计入下一轮 Findings |

## D-07: 后置条件
- Review Loop 已完成（PASS 或 ESCALATED）
- 所有轮次的审查报告已归档

## D-08: 副作用
- 创建多个 `{stage}_logs/round-{N}-*.md` 文件
- 通过编排器触发 Fixer skills

## D-09: 性能要求
- **响应时间**: 单轮 < 2 分钟，完整 loop < 10 分钟
- **吞吐量**: 最多 3 轮
- **资源消耗**: 中等（多次文档读写）

## D-10: 安全要求
- **数据隐私**: 不上传用户文档
- **权限控制**: 读取文档 + 写入审查日志
- **输入验证**: 验证轮次编号有效性

## D-11: 并发要求
- **并发模式**: 串行执行（Round 1 → Round 2 → Round 3）
- **冲突处理**: 不适用

## D-12: 数据一致性
- **状态一致性**: 每轮结束时状态明确（PASS/FAIL/ESCALATED）
- **历史一致性**: 每轮记录完整，可被后续轮次读取

## D-13: 可观测性
- **日志**: 每轮审查报告
- **追踪**: 通过 Round 编号追踪

## D-14: 部署约束
- **运行环境**: Claude Code CLI
- **依赖**: FT-001~FT-006, FT-008, FT-009

## D-15: 依赖关系
- **上游依赖**: FT-001（核心框架）、FT-005（决策引擎）、FT-008（编排器协议）
- **下游依赖**: FT-009（归档体系）
- **Feature 依赖**: FT-001, FT-005, FT-008, FT-009

## D-16: 实现映射
- **入口文件**: `skills/pb-review-v2/SKILL.md`（Workflow 主流程）
- **核心逻辑**: Round 计数器 + PASS/FAIL/ESCALATE 状态机
- **配置文件**: 无（循环逻辑内建于 SKILL.md Strategy 层）
