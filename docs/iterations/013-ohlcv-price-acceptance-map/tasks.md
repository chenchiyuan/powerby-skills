## 1. 需求与实现对齐

### 核心目标复述
- 基于单交易对、单周期、最近 `N` 根 OHLCV，构建一张历史价格接受度地图。
- 核心算法定义为：单根 K 线的 `time_weight * volume` 在其 `[low, high]` 覆盖到的 `micro bins` 中均匀分配，并归一化为 `price_acceptance_probability`。
- 一期同时交付三类消费形态：
  - Python 计算核心
  - CLI JSON 输出
  - 静态 Web 结果展示页

### 范围边界
- **本次实现（P0）**:
  - FT-001 输入校验与标准化
  - FT-002 固定 `100` 份微价格轴
  - FT-003 指数衰减成交量分配引擎
  - FT-004 区域插件框架
  - FT-005 `equal_width` / `adaptive_volatility` 插件
  - FT-006 区域聚合、热力图与诊断输出
  - FT-007 CLI JSON 入口
  - FT-008 静态 Web 结果展示页
- **明确排除**:
  - Monte Carlo 主链路
  - 数据库存储、HTTP API、任务队列
  - 交易建议、信号、自动下单逻辑
  - 超出文档合同的额外区域算法

## 2. 技术方案

### 方案 A：直接做单文件脚本，把校验、算法、CLI 全塞在一起
- **优点**: 开发速度快
- **缺点**: 无法承接区域插件、聚合器和 Web 消费层，测试颗粒度差

### 方案 B：按架构拆成纯计算核心 + 区域插件 + 输出适配层
- **优点**: 与 `architecture.md` 一致，可测试性强，CLI 和 Web 可共享同一结果合同
- **缺点**: 初始文件数更多

### 我的建议
- **推荐方案**: 方案 B
- **原因**: 它与 `architecture.md`、`FT-001 ~ FT-008` 的实现映射完全一致，也最适合按 TDD 分模块落地。
