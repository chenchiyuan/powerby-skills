# FT-003: orchestrator 状态管理

## 基本信息
- **Feature ID**: FT-003
- **功能名称**: orchestrator 状态管理
- **对应需求**: F-003
- **功能类型**: 调度层
- **优先级**: 必须（P0）
- **状态**: 待实现

## D-01: 功能标识
- **Feature ID**: FT-003
- **入口类型**: Skill（orchestrator 内部能力）
- **入口路径**: `skills/pb-v1-orchestrator/SKILL.md`

## D-02: 输入规格
| 参数名 | 类型 | 必填 | 约束 | 默认值 | 示例 |
|--------|------|------|------|--------|------|
| iteration_dir | string | 是 | 有效的迭代目录路径 | - | docs/iterations/015-pb-v1-flow-autoprogression/ |
| skill_result | object | 否 | 上一个 Skill 的执行结果 | 无 | { skill: "drafting", status: "completed" } |
| mode_switch | string | 否 | auto 或 manual | 不切换 | "manual" |

## D-03: 前置条件
- 迭代目录存在
- orchestrator 拥有迭代目录的写权限

## D-04: 正常输出
- `flow-state.md` 包含以下区块：
  - 基本信息：流程类型、当前模式（auto/manual）、启动时间、最后更新
  - 阶段进度表：每个 Skill 的状态（⏳待执行/🔄进行中/✅完成/❌FAIL/⛔Gate命中/🚨ESCALATED）
  - Gate 命中记录：时间、Gate 类型、Skill、问题、用户决策
  - 假设记录：AUTO_DECIDE_WITH_ASSUMPTION 的决策索引
  - Refinery 记录：reviewer 回流修复的轮次和结果

## D-05: 异常行为
| 错误码 | 触发条件 | 行为 | 错误消息 |
|--------|---------|------|---------|
| ERR-STATE-001 | flow-state.md 格式损坏 | 基于文件系统重建状态 | "flow-state.md 格式损坏，已基于文件系统重建" |
| ERR-STATE-002 | 阶段进度与文件系统不一致 | 以文件系统为准修正 | "状态修正: {skill} 标记为完成但产物 {path} 不存在" |
| ERR-STATE-003 | 迭代目录不存在 | 快速失败 | "迭代目录不存在: {path}" |

## D-06: 边界值
- flow-state.md 不存在 → 初始化新状态文档（所有 Skill 为⏳待执行）
- flow-state.md 存在但为空 → 视为格式损坏，重建
- mode 切换时有 agent 正在执行 → 等待当前 agent 完成后切换
- 同一 Skill 多次执行（Refinery）→ 阶段进度表保留最新状态，Refinery 记录追加

## D-07: 后置条件
- flow-state.md 与文件系统实际产物一致
- 模式切换已生效并持久化
- 状态变更有时间戳记录

## D-08: 副作用
- 创建或更新 flow-state.md
- 不修改任何其他产物文档

## 测试维度

### D-17: Test Oracle
**成功输出 Schema**:
```yaml
flow_state:
  basic_info:
    flow_type: enum [standard, quick, bugfix]
    mode: enum [auto, manual]
    started_at: ISO8601
    updated_at: ISO8601
  progress_table:
    - skill: string
      phase: enum [Think, Plan, Build, Test, Ship, Reflect]
      status: enum [pending, in_progress, completed, fail, gate_hit, escalated]
      completed_at: optional ISO8601
      artifact_path: optional string
  gate_records: array
  assumption_records: array
  refinery_records: array
```

**业务规则**:
- flow-state.md 与文件系统不一致时，以文件系统为准
- 状态只能前进（pending→in_progress→completed），不能回退（除非 Refinery 回流）
- mode 切换立即生效，不影响已完成的状态

## 架构维度

### D-09: 性能要求
- flow-state.md 读写延迟：< 100ms（本地文件系统）
- 状态更新频率：每次 Skill 完成后一次

### D-10: 安全约束
- flow-state.md 不含敏感信息
- 只有 orchestrator 写入，其他 Skill 只读

### D-11: 幂等性
- 状态更新幂等：同一 completion_signal 重复处理产生相同状态

### D-12: 事务性
- 单文件写入，原子性由文件系统保证

### D-13: 可观测性
- flow-state.md 本身即完整的可观测记录
- 阶段进度、Gate 记录、假设记录、Refinery 记录全部持久化

### D-14: 降级策略
- flow-state.md 损坏 → 基于文件系统重建
- flow-state.md 与文件系统不一致 → 以文件系统为准修正

### D-15: 依赖关系
- **上游**: completion_signal（触发状态更新）
- **下游**: orchestrator 调度决策（读取状态）
- **下游**: pb-v1-resume（扫描状态）

### D-16: 实现映射
- **入口文件**: skills/pb-v1-orchestrator/SKILL.md（内嵌能力）
- **产物**: {iteration_dir}/flow-state.md
- **变更类型**: NEW（全新状态文档格式）
